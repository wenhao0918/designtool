# 设计语言到OCCT码转换系统 · 顶层设计说明书（简版 V1.0）

### 一、 问题阐述（来龙去脉）
**背景**：用户使用自然语言描述设计意图（如“做个空心球”），但内核（OCCT矩阵）只认确定性的数据。LLM天然不可靠（无法保证复杂格式如JSON），因此不能把结构化任务交给它。
**目标**：找出一种**100%可靠、极简、不依赖LLM结构化能力**的翻译方式，将自然语言变成内核可执行的确定性数据。

### 二、 为什么采用“译码”（设计推演）
**核心洞察**：既然LLM会写错复杂结构（JSON/矩阵），那就干脆**禁止它写结构**。
**结论**：只给它一张**查码表**。LLM的唯一工作是“识别用户话里的词汇，然后翻译为对应的数字串”。数字（整数）是原子的，不存在语法错误，只存在查表对错。这就像发电报：发报员只负责把字翻译成数字，不负责设计电文格式。

### 三、 定下的结论（规范与规则）

**1. 全局唯一译码表（1~1000）**
通过一张静态映射表，将设计语言功能要素固定编号（以《OCCT_Codetable_V1.md》为唯一来源）：
- `1~99`：基础几何/体元（1=长方体，2=圆柱，4=球...；正方体=长宽高相等的长方体，不单占编号）
- `100~199`：布尔算子（100=并，101=减，102=交...）
- `200~299`：修饰算子（200=倒圆角，202=抽壳，207=打孔...）
- `300~399`：变换算子（300=平移，301=旋转...）
- `400~499`：坐标系（401=X轴偏移...）
- `500~599`：材质；`600~699`：约束；`700~749`：IO；`750~799`：空间关系/装配定位；`800~899`：复合与标准件；`990~999`：引用与控制算子

**2. LLM（译码员）规则：纯数字序列输出**
- **输入**：用户自然语言。
- **输出**：仅是一串数字数组（用空格或逗号分隔）。**严禁输出JSON、严禁输出括号、严禁输出标签。**
- **示例**：
  - 用户：“做个正方体” -> `1, 50.0, 50.0, 50.0`（1=长方体，长宽高相等即正方体）
  - 用户：“长方体挖个圆柱洞” -> `1, …, 2, …, 101, 992, 991`（长方体=1，圆柱=2，减=101；992=先建的长方体，991=后建的圆柱刀具）
  - 用户：“边长为50的正方体” -> `1, 50.0, 50.0, 50.0`（数字后紧跟着浮点参数）
- **纠错**：如果LLM遇到无法映射的词（如方言/未收录词），按规则强制输出特定错误码，例如 `9999`，以触发系统报警。

**3. 内核（收报机）规则：盲扫描与执行**
- 内核拿到这串数字，**直接按顺序逐个查表执行**。
- **无嵌套、无上下文判断**。例如 `1, …, 2, …, 101, 992, 991`，内核直接查找1（创建长方体），查找2（创建圆柱），查找101（做减法），底层OCCT调用按此顺序完成几何构建。
- **校验规则**：如果数字不在1~1000内，系统判定为`TRANSLATE_ERROR`，直接拒绝执行并要求LLM重译。这就是确定的、唯一的、极其纯粹的收报机。

**4. 人工纠正（回显机制）**
- 内核按数字流执行前，前端将数字流**反查**为人类可读的词语（`1`反查为“长方体”）。
- 用户看到`1, …, 2, …, 101, 992, 991`（即：长方体 - 圆柱），即可直观判断正误。
- 若错误，用户只需告诉LLM“第二个应该是4（球）”，LLM重发一串新数字，内核再次执行。不需要复杂回滚，直接用新的数字串覆盖即可。

### 四、 交付给AI Code的落地指令（极简版）

请AI Code按以下顺序实现，**不添加任何额外结构**：

1. **建表（Data层）**：用 `unordered_map<int, string>` 实现静态译码表。
2. **接口（LLM接入）**：调用LLM（设置极简Prompt：只准输出数字序列，不准输出其他文字）。
3. **解析（Paser）**：写一个简单的 `split` 函数，解析LLM返回的字符串，提取数字数组。
4. **执行（Executor）**：遍历数字数组，通过 `switch` 或查表调用对应的 OCCT 底层函数。
5. **校验（Validator）**：如果出现不是合法编码的数字，直接抛出 `ILLEGAL_CODE` 并中断执行。
6. **回显（UI）**：提供“反查函数”，把数字流翻译成中文，展现在前端供用户确认。
