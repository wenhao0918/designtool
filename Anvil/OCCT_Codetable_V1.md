# OCCT 码映射表 V1

> 配套《Anvil_Translator_Spec_V1.md》。本表是 LLM 译码员 / 内核收报机 / 前端回显三方对齐的唯一映射表。
> 编制依据：OpenCASCADE Technology 8.0（OCCT）。
> 粒度：**设计语言功能要素级**——每行是一个用户设计指令里能出现的功能（球/抽壳/并/平移…），不是 OCCT 内部类。OCCT 类名只在"执行入口"列出现，作为内核怎么调的落点，不单独占编号。

## 三方如何用这张表

| 角色 | 用法 | 例子 |
|---|---|---|
| LLM 译码员 | 用户话 → 数字串（正向查"用户语义"列） | "空心球直径100壁厚10" → `4, 50.0, 4, 40.0, 101, 992, 991`（外球−内球） |
| 内核收报机 | 数字 → 底层实现调用（查"执行入口"列） | `4`→`BRepPrimAPI_MakeSphere`，`101`→`BRepAlgoAPI_Cut` |
| 前端回显 | 数字 → 中文词（反查"用户语义"列） | `4, 50.0, 4, 40.0, 101, 992, 991` → 球(r=50)·球(r=40)·减 |

## 两套编号（关键区分）

| 类别 | 范围 | 性质 | 例子 |
|---|---|---|---|
| **译码表编号** | 1~999 | 静态·固定·功能要素 | `4` = 球（这个功能） |
| **对象指称·指令序号** | 正整数·自动递增 | 运行时·唯一·永不复用 | `#1` = 第1条指令产生的对象 |

- **译码表编号**：本表里 1~999 的固定编号，表示"做什么"（球/抽壳/并…）
- **对象指称=指令序号**：每条用户指令由系统分配一个自动递增的序号（1,2,3…）。序号即该指令产生对象的唯一指称代码，永不复用。后续指令通过 `990` 引用算子引用该序号来定位/装配
- **一条指令一个序号**：即使指令内部有多个操作（如"长方体+圆柱+减"=`1,参数…,2,参数…,101,992,991`），也只产**一个最终结果对象**，对应一个序号；中间过程对象不单独编号（991=本指令最新体，992=次新体）
- **错误码**：无法映射输出 `9999`；数字不在表内判 `TRANSLATE_ERROR`

## dltQ 矩阵形态（带指令序号）

每个 ΔQ = 一条用户指令 = 一个序号 + 一串数字：

```
#序号: 功能编号, 参数..., [引用算子, 被引用序号]...
```

- 序号由系统自动递增分配，LLM 只负责写"功能编号+参数+引用"
- 引用已有对象用 `990` 算子 + 被引用序号
- 无引用的简单指令就是 `#序号: 功能编号, 参数...`

## 参数约定

- 参数是浮点数，紧跟在触发的功能要素编号后，按"参数签名"列顺序排列
- 无参数的功能要素（如布尔算子）后不跟参数
- 范例："边长50的正方体" = `#1: 1, 50.0, 50.0, 50.0`（1=长方体，长宽高相等即正方体；正方体不单占编号）

## 别名与同义词处理（分层架构，防主表爆炸）

**核心原则**：主表每个功能要素只列一个**主词**（standard_term），别名/同义词/方言/口语**不进主表**，否则每个功能要素要为"方块/盒子/立方体/方体/方盒"等几十种说法各占一行，主表立刻爆炸。

**分层职责**（别名处理归知音模块，不归译码）：

| 层 | 职责 | 输入→输出 |
|---|---|---|
| 知音（Zhiyin） | 自然语言归一化：别名/同义词/歧义消解 | 用户话 → 主词 |
| 译码（本表） | 主词→编号查表 | 主词 → 码编号 |
| 内核 | 编号→OCCT执行 | 编号 → OCCT API 调用 |

**数据流**：
```
用户："做个方盒子，边长50"
  ↓
知音：别名索引+RAG向量召回 → 归一为 "长方体"(standard_term)
  ↓
译码：查主表 "长方体" = 编号1
  ↓
内核：BRepPrimAPI_MakeBox(50, 50, 50)
```

**与知音对齐**（[Zhiyin/ARCHITECTURE.md](file:///Users/dengwenhao/develop/work/dao_code/DesignTool/Zhiyin/ARCHITECTURE.md)）：
- 知音 MySQL schema：`id, standard_term, category, json_expressions, mapping, constraints`
  - `standard_term` = 主词，与主表"用户语义"列对齐
  - `json_expressions` = 别名字段（"方块/盒子/立方体/方体"等），归知音维护
- 主表只保留 `编号 ↔ 主词 ↔ OCCT执行入口` 三列，不存别名
- LLM 译码员拿到的输入是知音归一化后的主词，不是用户原始方言

**主表维护纪律**：新增功能要素时只填主词一行；新别名只更新知音 `json_expressions`，不动主表。

## 范例：完整译码过程

### 范例1·单条指令（空心球）

**用户设计指令**："设计一个空心球，直径100mm，壁厚10mm"

**系统分配序号 #1**。LLM 译码（组合式：空心球=外球−内球，不查表，按收编标准组合表达）：
```
#1: 4, 50.0, 4, 40.0, 101, 992, 991
```
分解：
- `4,50.0` = 外球（BRepPrimAPI_MakeSphere，直径100/2）
- `4,40.0` = 内球（直径 = 100 − 2×10 = 80，半径40）
- `101` = 减算子（BRepAlgoAPI_Cut）
- `992` = 上一对象（外球，被减体）
- `991` = 当前对象（内球，刀具）

**内核执行**：
1. `4,50.0` → `BRepPrimAPI_MakeSphere(r=50)` → 外球
