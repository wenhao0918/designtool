# 设计原语机制（Design Primitives Mechanism）

> 状态：架构讨论结论 · 2026-08-14
> 定位：DesignTool 面向所有设计任务的核心机制设计文档

---

## 1. 问题：当前原语只是"转了一道"

现状链路：

```
LLM → 原语调用（shell_box(L=400, W=360, H=200, t=8)）→ 原语函数 → FreeCAD 代码 → STEP
```

这条链路与 `LLM → 直接写 FreeCAD 代码` 在本质上没有区别：

- **解决了（语法层）**：LLM 不用记 FreeCAD API、不用处理坐标系平移、不用写布尔运算。
  错误空间从"无限"收缩到"参数值"。
- **没解决（推理层）**：L/W/H/t 这些值仍然是 LLM 拍的。尺寸从哪来？没有来源。
  LLM 报 `shell_box(400, 360, 200, 8)` 与写 `Part.makeBox(400,360,200)` 是同一个几何决策。

结论：当前原语是"让 LLM 少写错代码"，不是"让 LLM 少做几何推理"。
LLM 空间几何为零的瓶颈没有解决，只是换了输出格式。

---

## 2. 目标：把几何决策从 LLM 手里拿走

### 2.1 五层架构

```
┌─────────────────────────────────────────────┐
│  L1 意图层   用户自然语言（需求/约束/场景）        │
├─────────────────────────────────────────────┤
│  L2 语义层   LLM：需求理解、方案选型、组合编排      │ ← LLM 擅长，保留
├─────────────────────────────────────────────┤
│  L3 推导层   参数推导：力学/人因/标准/溯源          │ ← 工具，LLM 不碰
├─────────────────────────────────────────────┤
│  L4 几何层   原语：参数 → 几何（含装配约束）        │ ← 工具，LLM 不碰
├─────────────────────────────────────────────┤
│  L5 验证层   干涉/运动学/强度/尺寸合理性            │ ← 工具，自动
└─────────────────────────────────────────────┘
```

核心原则：**LLM 只做 L2（语义层），L3–L5 全部是工具**。
LLM 下订单，车间按工艺卡生产。

### 2.2 类比

- 现状：LLM 填 CAD 对话框参数——本质还是它在设计。
- 目标：LLM 说"我要一个承重 80kg 的折叠铰链"——工具从力学计算和标准里找答案。

---

## 3. 四个升级机制

### 3.1 参数必须有来源，禁止拍脑袋

LLM 输入"承重 80kg 的折叠铰链" → 推导层计算：

- 销径：按剪切强度 `d ≥ √(4F / (n·π·τ))`
- 耳板厚度：按许用应力
- 安全系数：静载 ≥ 1.5，动载 ≥ 2.0

每个参数带**溯源链**：力学公式 / GB 标准值 / 人因数据 / 用户指定。
LLM 无权凭空给数字；给不出来源的参数一律拒绝。

落地：接入 param-derive 平台（参数推导工作台），原语参数声明
`source: derive | user | standard` 三种来源，`derive` 类必须走推导工具。

### 3.2 装配约束收进原语契约

配对原语之间定义**强约束**，LLM 只选类型、不排细节：

| 配对 | 约束 |
|------|------|
| side_shaft ↔ side_hole | 同轴、间隙 0.1mm、左右成对 |
| u_channel ↔ u_channel_bellows | 截面尺寸自动匹配 |
| 铰链两耳座 | 同轴、销贯穿、耳间距匹配 |

LLM 说"这里要个枢轴"，工具自动保证两零件同轴、尺寸匹配、成对布置。
装配关系变成原语间的契约，LLM 无法破坏。

### 3.3 几何自校验，不合格拒绝

原语内部校验，不通过直接拒绝并说明原因，不生成垃圾 STEP：

- 壁厚过薄（< 制造下限）
- 长宽比畸形
- 与已有零件干涉
- 运动件行程/旋转范围越界

LLM 报参数的自由度被约束在合理域内。

### 3.4 LLM 角色收敛

| 保留（LLM 擅长） | 移走（LLM 不擅长） |
|------------------|-------------------|
| 需求理解 | 几何计算 |
| 方案选型 | 力学计算 |
| 组合编排 | 装配关系 |
| 设计意图表达 | 参数取值 |

---

## 4. 与现有资产的关系

- **17 个原语**：保留作为 L4 几何层，补参数来源声明 + 装配契约 + 自校验。
- **param-derive 平台**：接入 L3 推导层，是本次升级的核心依赖。
- **Anvil / DesignAgent**：L2 语义层不变，工具描述更新为"选型/编排"语义。
- **dtwin / spatial**：L5 验证层（干涉、运动学、强度）已有基础，补齐自动触发。

---

## 5. 落地路径（优先级）

1. **P0** 原语参数加 `source` 声明 + 推导层接口（param-derive 接入）
2. **P0** 配对原语装配契约（side_shaft/side_hole、u_channel/bellows）
3. **P1** 几何自校验（壁厚/比例/干涉拒绝）
4. **P1** 提示词与工具描述按"LLM 只做语义层"重写
5. **P2** 验证层自动触发（建模后自动跑干涉/强度，不合格回退）

> 原则：不新增原语数量，先把已有原语的约束和来源做扎实。
> 判断标准：LLM 报参数时给不出来源 → 架构失败；给得出来源 → 架构成立。
