# DesignTool 平台开发指南

> 本文档是用户对 DesignTool 平台组件的完整思考过程总结。核心结论：平台的终极目标是构建机械 AI 的内核——基于物理约束的建模与求解管道。从大学理论力学课程体系出发，逐层推进到机械 AI 的内核构建，最终收敛为可执行的开发路线图。

> **核心结论：整个思考过程的最终指向——DesignTool 平台的终极目标不是做一个更好的 CAD 工具，而是构建机械 AI 的内核。这也是本指南的重中之重。**

## 二、机械 AI 内核构建——平台的核心目标

> 来源：S-013, S-009, S-008, S-012

整个思考过程的每一条线索，最终汇聚到一个结论：**DesignTool 平台的核心使命不是做更好的 CAD 工具，而是构建机械 AI 的内核。**

### 2.1 内核是什么

机械 AI 的内核 = **基于物理约束的建模与求解管道**。它从底层区别于 LLM——LLM 只是工具层的翻译器。内核的组成：

| 组件 | 学科来源 | 求解方法 |
|:-----|:-----|:-----|
| 固体力学分析 | 理论力学 + 材料力学 | FEM（有限元法，CalculiX） |
| 流体力学分析 | 流体力学 | CFD（有限体积法，OpenFOAM） |
| 多体动力学 | 理论力学进阶 | MBD（刚体/柔体运动求解） |
| 拓扑优化 | 变分原理 | 生成式设计——自动挖掉不承力材料 |

**内核层的 AI 不是 Transformer**，而是 PINN（物理信息神经网络）或神经算子——用神经网络逼近微分方程的解，底层逻辑是牛顿和纳维-斯托克斯。

### 2.2 内核的三层约束传递链

约束从工程现场一路传递到求解器内部（S-009）：

```
机械设计约束          →  理论力学约束        →  AI 约束
（铰链/导轨/齿轮啮合）    （约束方程/虚位移原理）   （硬约束砍掉非法解）
```

| 层 | 来源 | 在内核中的角色 |
|:-----|:-----|:-----|
| 几何约束 | 固定铰链、光滑接触 | 硬约束——AI 输出直接被砍掉 |
| 运动约束 | 只滚不滑、无摩擦 | 物理信息约束——损失函数的罚项 |
| 性能约束 | 重量最轻、刚度最大 | 目标函数——拓扑优化的优化方向 |

### 2.3 内核的运作方式——五步闭环

内核不是一次性计算，是递归迭代的闭环（S-015, S-016）：

```
意图检索 → 结构设计 → 力学验算 → 选优 → 收敛
    ↑                                              │
    └──────────── 反馈修正 ←────────────────────────┘
```

每一步都在给上一步打补丁，同时给下一步埋伏笔。设计师（总架构师）在每个环节深度参与——不是按按钮的操作员，是那个随时暂停、调参、重跑的临场决策者（S-017）。

### 2.4 内核的三大支点（理论力学的三个分支）

理论力学不是内核的全部，但它是内核最重要的支点之一（S-008）：

| 支点 | 在内核中的角色 | 硬约束 |
|:-----|:-----|:-----|
| 静力学 | 地基校验员 | 力平衡 + 摩擦自锁——重心不在支撑面内，直接过滤 |
| 运动学 | 轨迹审计师 | 速度瞬心 + 刚体平面运动——连杆卡死、干涉，一票否决 |
| 动力学 | 能量总管 | 动能定理 + 拉格朗日方程——1000 条轨迹，哪条最省电 |

### 2.5 当前 DesignTool 与内核的差距

DesignTool 的上半场（意图检索 → 结构设计）已经跑通。但内核的核心——物理求解——目前是断点（S-019）：

| 内核环节 | 状态 | 缺失的模块 |
|:-----|:-----|:-----|
| 力学验算 | ❌ 断点 | FEM 封装层——scene JSON 不含 `constraints` 字段，无 CalculiX 调用 |
| 选优 | ❌ 未实现 | 多目标评分器——无方案比较与权重体系 |
| 收敛 | ❌ 未实现 | 迭代控制器——无「生成→验算→反馈→重新生成」的闭环 |

**这就是后续开发路线要填的坑。** 优先级 A（FEM 封装层）是内核构建的起点。

## 三、关键结论

### 3.1 DesignTool 的定位

DesignTool 是「AI 与设计意图之间的桥梁」，不是 CAD 替代品。它叠加在 FreeCAD 等成熟工具之上的信息层，负责将隐性设计意图转化为 AI 可读的显性结构。

**三条原则**：
1. 不取代成熟开源工具
2. 表达更多信息、语义、意图、抽象
3. 便于 AI 处理、理解和加工

### 3.2 当前状态：上半场跑通

| 环节 | 完成度 | 对应模块 |
|:-----|:-----|:-----|
| 意图检索 | ✅ | Intent/Semantics/Context/Timeline 四层 + SketchPad 多模态输入 |
| 结构设计 | ✅ | 18 原语 → FreeCAD → STEP |

### 3.3 缺失的下半场

| 环节 | 完成度 | 需要做的事 |
|:-----|:-----|:-----|
| 力学验算 | ❌ | FEM 封装层（调用 CalculiX），scene JSON 扩展 `constraints` 字段 |
| 选优 | ❌ | 多目标评分器（重量/应力/变形/成本归一化），设计师权重滑块的交互界面 |
| 收敛 | ❌ | 迭代控制器——生成→验算→选优→反馈给意图层→重新生成，直至变化低于阈值 |

### 3.4 机械 AI 的架构分层

```
┌──────────────────────────────────────────┐
│  工具层（LLM）                             │
│  自然语言 → 约束代码、解读报错、生成报告    │
├──────────────────────────────────────────┤
│  内核层（物理引擎 = PDE 求解器）            │
│  FEM（固体）/ CFD（流体）/ MBD（多体）      │
│  PINN / 神经算子                           │
├──────────────────────────────────────────┤
│  调度层（总架构师 = 设计师）                │
│  定义评价标准、裁定物理优先序                │
│  校验物理直觉、选择求解精度                 │
└──────────────────────────────────────────┘
```

### 3.5 总架构师的四项不可替代的决策权

1. **定义评价标准**——重量最轻 / 刚度最大 / 成本最低（AI 需要你定靶心）
2. **裁定物理优先序**——硬约束（死命令）vs 软约束（可妥协）
3. **校验物理直觉**——力流是否连续、是否存在突变截面
4. **选择求解精度**——线性 vs 非线性、网格密度

## 四、后续开发路线

### 优先级 A：补力学验算（下一个里程碑）

**目标**：让 DesignTool 从「能画出来」升级为「能算一遍」。

**具体任务**：
1. 在 `ParamDerive/` 中实现 FEM 封装层，调用 FreeCAD 的 CalculiX 求解器
2. 扩展 scene JSON 协议，新增 `constraints` 字段，承载边界条件：
   ```json
   {
     "constraints": {
       "fixed": [{"type": "face", "target": "bottom", "coordinate": [0, 0, -1]}],
       "loads": [{"type": "pressure", "target": "top", "value": 1000, "unit": "N"}],
       "material": {"yield_strength": 250, "unit": "MPa"}
     }
   }
   ```
3. 输入：scene JSON + 载荷/约束条件 → 输出：应力云图、变形量、安全系数

**输入来源**：S-019 对照分析

### 优先级 B：实现选优体系

**目标**：让 AI 生成的多个方案可以被自动比较和排序。

**具体任务**：
1. 在 `verify.py` 中实现多目标评分器
2. 归一化指标：重量、最大应力、变形量、成本
3. 前端增加设计师权重滑块——轻量化权重 60%、刚度权重 40%，系统自动重排

**输入来源**：S-014 四项决策权、S-017 Human-in-the-loop

### 优先级 C：实现收敛闭环

**目标**：从一次性生成升级为递归迭代。

**具体任务**：
1. 在 `agent.py` 中增加迭代控制器
2. 核心循环：生成 → 验算 → 选优 → 反馈给意图层 → 重新生成
3. 终止条件：连续两次迭代的变化量 < 设定阈值

**输入来源**：S-015 五步闭环、S-016 递归迭代

### 优先级 D：知识库建设

**目标**：将理论力学/材料力学/流体力学的物理约束沉淀为可复用的知识资产。

**具体任务**：
1. 建立标准约束库（固定铰链、光滑接触、自锁条件等）
2. 建立材料数据库（屈服强度、疲劳极限、密度等）
3. 用 TraceTool 管理所有知识资产的溯源链

**输入来源**：S-001–S-006 理论力学体系；S-009 约束泛化三层

## 六、一句话总结

> **DesignTool 的终极目标不是做更好的 CAD 工具，而是构建机械 AI 的内核——一个基于物理约束的建模与求解管道。上半场（意图→几何体）已跑通，下半场（FEM 封装→多方案选优→递归收敛）是内核构建的主战场。理论力学是内核最重要的支点，约束泛化是内核的底层逻辑，五步闭环是内核的运作方式。Human-in-the-loop 的总架构师，是内核的灵魂。**
