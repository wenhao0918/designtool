# 标准件/非标件查询系统设计

> 机械 AI「意图检索」环节的核心支撑——设计师要知道「有什么现成零件可用」，才能给 AI 下达正确的设计意图。

## 一、为什么需要这套系统

yhdfa.com（怡合达）的模式揭示了机械设计的现实：**大量设计不是从零开始，而是在标准件/非标件基础上组合、适配、优化。**

放在机械 AI 的五步闭环里——「意图检索」环节的核心问题之一是「有什么现有有效结构可参考？」这个问题如果只能靠设计师的记忆和经验来回答，AI 辅助设计的天花板就在那里。

标准件查询系统就是「意图检索」的外化数据库。

## 二、与现有 cloud-base 体系的关系

cloud-base-backend 已有：
- 完整的 Dromara 框架（认证/租户/CRUD 脚手架）
- qy-material 模块（物料管理基础）
- BidAnalysisResult（标书分析→物料提取的链路）

cloud-base-ui 已有：
- materialMarketQuery（AI 对话式物料查询界面）
- 多种物料类型的 view/api 目录结构

本系统作为 **qy-material 的新子模块** 加入，复用现有框架和前端布局。

## 三、领域模型

### 3.1 标准件分类（参考 yhdfa.com 的类目体系）

```
FA 工厂自动化零部件
├── 直线运动零件
│   ├── 直线导轨
│   ├── 滚珠丝杠
│   ├── 直线轴承
│   └── 导向轴
├── 旋转运动零件
│   ├── 轴承
│   ├── 联轴器
│   └── 同步带轮
├── 紧固零件
│   ├── 螺栓/螺钉
│   ├── 螺母
│   └── 垫圈
├── 驱动零件
│   ├── 电机
│   ├── 气缸
│   └── 减速机
├── 结构零件
│   ├── 型材
│   ├── 支架
│   └── 面板
└── 电气零件
    ├── 传感器
    ├── 开关
    └── 线缆
```

### 3.2 核心实体

| 实体 | 说明 | 关键字段 |
|:-----|:-----|:-----|
| PartCategory | 分类树 | name, parent_id, level, sort |
| StandardPart | 标准件 | category_id, brand, model, specs(JSON), 3d_model_url |
| NonStandardPart | 非标件/定制件 | category_id, description, parameters, supplier |
| PartSpec | 规格参数模板 | category_id, spec_schema(JSON) |

### 3.3 规格参数的 JSON Schema 设计

不同类别的零件有不同的参数。比如直线导轨：

```json
{
  "specs": {
    "rail_width": {"value": 15, "unit": "mm"},
    "rail_length": {"value": 300, "unit": "mm"},
    "block_type": "法兰型",
    "load_capacity": {"dynamic": 5.2, "static": 8.6, "unit": "kN"},
    "material": "GCr15",
    "precision_grade": "P"
  }
}
```

## 四、API 设计

### 4.1 分类浏览

```
GET /material/partCategory/tree          → 完整分类树
GET /material/partCategory/{id}/children → 下级分类
```

### 4.2 零件检索

```
GET /material/standardPart/list?categoryId=1&keyword=导轨&brand=THK&page=1&size=20
GET /material/standardPart/{id}           → 详情
POST /material/standardPart/search        → 高级检索（按规格参数范围）
```

### 4.3 规格查询

```
GET /material/partSpec/{categoryId}       → 某分类的规格参数模板
```

### 4.4 与 DesignTool 的对接

```
GET /material/standardPart/match?specs={json}  → 根据约束条件匹配标准件
```

这个端点直接服务于「意图检索」——设计师说「承重 1 吨的支架」，系统能返回相关的标准型材和连接件。

## 五、前端界面

复用 cloud-base-ui 的现有 pattern，新增两个页面：

| 页面 | 路由 | 功能 |
|:-----|:-----|:-----|
| 标准件分类浏览 | `/material/partCatalog` | 左侧分类树 + 右侧零件列表 + 规格筛选 |
| 零件详情 | `/material/partCatalog/:id` | 规格参数表 + 3D 预览（if possible）+ 供应商信息 |

已有 `materialMarketQuery` 的 AI 对话式查询可以保留，作为自然语言入口。

## 六、数据来源

初期手动录入核心分类和常用标准件。中长期：
- 爬取 yhdfa.com 等平台的公开规格数据（需注意合规）
- 对接供应商 API
- 从标书分析结果中自动提取物料需求

## 七、与 DesignTool 的集成点

这是最关键的设计决策：标准件查询系统如何嵌入机械 AI 的五步闭环？

```
意图检索阶段：
  设计师输入需求 → 系统推荐标准件 → 设计师选定 → 生成 scene JSON 的 reference 字段

结构设计阶段：
  AI 生成方案时，从标准件库中选取匹配的零件，而非从零建模

示例 scene JSON 扩展：
{
  "components": [
    {
      "type": "standard_part",
      "part_id": "SP-00123",
      "part_name": "直线导轨 HGH15CA",
      "supplier": "THK",
      "transform": { "x": 100, "y": 200, "z": 0 }
    }
  ]
}
```
