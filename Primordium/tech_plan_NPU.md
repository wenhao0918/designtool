## 一、总体原则

本规划严格遵循Primordium的“问题→数学依据→完善理论”推进脉络，将CANN定位为**“场算子执行器”**——专责执行变分法离散化后的大规模稠密/稀疏矩阵运算（`Ax=b` 求解）。

**三条铁律**：

1. **绝不依赖数据**——不设训练集、验证集、测试集，仅输入物理常数（E, ν, ρ）与载荷边界。
2. **绝不依赖反向传播**——主循环采用共轭梯度法（CG）或牛顿-拉弗森法，而非SGD。
3. **硬约束即硬边界**——违反 `𝒫` 或 `ℳ` 的候选解直接判为无定义，不做平滑近似。

### 阶段一：数值线性代数基座——在NPU上实现共轭梯度法（CG）（第3-6周）

**目标**：在NPU上实现求解 `K(ρ)·u = F` 的共轭梯度法（CG）迭代器，这是约束场引擎的**数值心脏**。

**对应tech_base.md**：阶段二·离散化 → `[K]{u}={F}` 求解

**技术路线**：

| 步骤 | 任务 | CANN接口 | 对应理论 |
| :--- | :--- | :--- | :--- |
| 1.1 | 在CPU端生成稀疏刚度矩阵 `K`（CSR格式） | — | FEM离散 |
| 1.2 | 将 `K` 和 `F` 搬运至NPU显存 | `aclrtMemcpy` | 边界 ℬ |
| 1.3 | 实现CG迭代主循环（在NPU上执行） | — | 梯度流 ∇Φ |
| 1.4 | 稀疏矩阵-向量乘（SpMV） | `aclnnSparseMatMul` | 物理场 𝒫 |
| 1.5 | 向量点积与标量运算 | `aclnnDot` / `aclnnMul` | 价值场 𝒱 |
| 1.6 | 将结果 `u` 拷回CPU | `aclrtMemcpy` | 边界 ℬ |

**CG算法伪代码**（在NPU上执行的每一步）：

```
r₀ = F - K·u₀,  p₀ = r₀
for k = 0, 1, 2, ... until convergence:
    αₖ = (rₖ·rₖ) / (pₖ·K·pₖ)     ← 两次SpMV + 点积
    uₖ₊₁ = uₖ + αₖ·pₖ             ← 向量更新
    rₖ₊₁ = rₖ - αₖ·K·pₖ           ← SpMV
    βₖ = (rₖ₊₁·rₖ₊₁) / (rₖ·rₖ)   ← 点积
    pₖ₊₁ = rₖ₊₁ + βₖ·pₖ           ← 向量更新
```

**验收标准**：对已知解析解的模型问题（如均匀悬臂梁），CG求解结果与CPU参考解误差 < 1e-6。

**⚠️ 关键技术决策**：
- 稀疏矩阵采用**CSR格式**存储，CANN的`aclnnSparseMatMul`原生支持。
- 所有向量运算（点积、更新）在NPU上完成，**避免每步迭代都做CPU-NPU数据搬运**。
- 收敛判断（残差范数）在NPU上计算后拷回单个标量即可。


### 阶段二：约束势 Φ 的组装——在NPU上计算梯度流（第7-10周）

**目标**：在阶段一基础上，将 `𝒫`、`ℳ`、`𝒱` 三场耦合编码为可计算的约束势 `Φ`，实现 `∇Φ(𝕄)=0` 的迭代求解。

**对应tech_base.md**：附录A · A.7 迭代格式（OC/MMA）

**核心迭代**（OC优化器，在NPU上执行）：

| 每步操作 | CANN接口 | 对应场 |
| :--- | :--- | :--- |
| 给定密度场 ρ⁽ᵏ⁾ | — | 设计变量 |
| 组装刚度矩阵 K(ρ) | CPU端组装（或Ascend C核内组装） | 制造场 ℳ |
| 求解 K·u = F（调用阶段一的CG求解器） | `aclnnSparseMatMul` | 物理场 𝒫 |
| 计算柔度 C = Fᵀ·u | `aclnnDot` | 价值场 𝒱 |
| 计算灵敏度 dC/dρ | 伴随法 → 矩阵-向量乘 | 价值场 𝒱 |
| 更新 ρ（OC准则，含体积分数投影） | 逐元素运算 + 硬截断 | 制造场 ℳ |

**验收标准**：对悬臂梁基准问题，优化后的拓扑结构与传统SIMP法一致，且**严格满足**体积分数约束（误差 < 1%）。

**⚠️ 关键技术决策**：
- 灵敏度计算采用**伴随法**（Adjoint Method），只需一次额外的CG求解，无需自动微分。
- 密度更新中的**硬截断**（ρ ∈ [0,1]）直接用`aclrtMemcpy`后的CPU端逻辑判断，或写成Ascend C核函数内的`max/min`指令。
- 体积分数投影（防止棋盘格）可采用**密度滤波**，在CPU端完成（低频操作，不构成性能瓶颈）。


### 阶段三：Ascend C自定义物理核——编写本构关系与非线性惩罚（第11-14周）

**目标**：当AOL标准算子不满足需求时，用Ascend C编写自定义核函数，实现理论中的**硬势垒**和**非线性本构**。

**对应tech_base.md**：第四部分·决裂宣言——硬约束 = 指示函数

**需要自定义的场景**：

| 场景 | 数学形式 | Ascend C实现 |
| :--- | :--- | :--- |
| 硬势垒（不可穿透边界） | `I_{g>0}·∞` | 矢量比较 + 条件赋值 |
| 超弹性本构（Neo-Hookean） | `Ψ = C₁(I₁-3) + ...` | 矢量计算 + 矩阵运算 |
| 应力约束的逐点检查 | `σ_vonMises ≤ [σ]` | 逐元素张量运算 |

**开发流程**：

```
1. 编写算子原型定义（json）→ msOpGen生成工程
2. 实现核函数（Ascend C）
3. Tiling策略设计（数据分块，适配NPU片上内存）
4. 编译为 `.o` 文件
5. 通过AscendCL加载并调用
```

**验收标准**：自定义硬势垒算子在NPU上的执行结果与CPU参考完全一致（非近似），且性能不低于AOL同类算子。

**⚠️ 关键技术决策**：
- 优先使用**AOL标准算子**（`aclnn`系列），仅在标准库不支持时启用Ascend C。
- Ascend C的**矢量计算API**（`Add`/`Mul`/`Compare`）是实现逐点硬约束的首选。
- **CATLASS模板库**可大幅降低Ascend C开发门槛，优先研究其五层模块化设计。


### 阶段四：混合架构集成——CPU逻辑 + NPU数值闭环（第15-18周）

**目标**：将L3（符号/拓扑层，CPU）与L2（数值计算层，NPU）集成，实现完整的“约束场引擎”原型。

**对应tech_base.md**：阶段三·软件架构（四层混合）

**架构示意**：

```
┌─────────────────────────────────────────────────────┐
│  L3: CPU（逻辑裁决）                                 │
│  - 可达性检查：𝒞ₚ ∩ 𝒞ₘ ≠ ∅                         │
│  - 递归深度判定（Base Case是否存在）                 │
│  - 收敛判断（残差 < ε）                             │
│  - 拓扑相变监控（孔洞生灭，预留接口）               │
└──────────────────────┬──────────────────────────────┘
                       │ 下发: ρ⁽ᵏ⁾, F, E, ν
                       │ 回收: u, C, dC/dρ
                       ▼
┌─────────────────────────────────────────────────────┐
│  L2: NPU（数值计算）← CANN                          │
│  - 阶段一：CG求解 K·u = F                          │
│  - 阶段二：约束势 Φ 的梯度流迭代                   │
│  - 阶段三：Ascend C自定义核（硬势垒/本构）         │
└─────────────────────────────────────────────────────┘
```

**验收标准**：完整的悬臂梁拓扑优化流程——输入 `(E, ν, F, V_f)`，输出最优拓扑——在NPU上完成，总耗时较纯CPU实现**提升 ≥ 10倍**。

**⚠️ 关键技术决策**：
- CPU与NPU之间通过**异步Stream**实现计算与数据传输的重叠。
- 拓扑变化检测（持续同调）**留在CPU**，不塞入NPU——这是“四肢不得指挥心脏”原则的体现。

**目标**：完成悬臂梁基准案例的完整验证，撰写技术报告。

| :--- | :--- |
| 精度验证 | NPU结果与CPU双精度参考解误差 < 1e-4（拓扑构型一致） |

## 五、风险与应对

| 风险 | 影响 | 应对策略 |
| :--- | :--- | :--- |
| NPU 稀疏矩阵算子性能不及预期 | 阶段一延迟 | 提前调研算子模板库，必要时手写 SpMV |
| 自定义算子学习曲线陡峭 | 阶段三延迟 | 优先复用开源算子模板 |
| CPU-NPU数据搬运成为瓶颈 | 整体性能不达标 | 采用异步Stream + 双缓冲，最大化计算与传输重叠 |
| 硬约束的“无穷大”在数值上难以处理 | 迭代不收敛 | 采用**障碍法（Barrier Method）**：硬势垒用 `-log(g(x))` 近似，随迭代逐步收紧 |
