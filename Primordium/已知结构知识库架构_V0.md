# 已知结构知识库架构 V0

> 版本: V0.1（2026-09-04）
> 上位: 《DesignTool架构定义_V0.md》§三（EG/RV 知识矩阵）、§4.1（知音接入）
> 关联: 《专利申请/技术交底书》§B 术语具名块展开、§A 意图漂移检测
> 一句话: **已知结构 = 高层术语具名块**——DB 存"机械原理"（结构/参数/约束/装配规则），RAG 存"标准条文"（依据/公式/案例），融合输出结构 JSON 供 Anvil 翻译为 ΔQ 骨架

---

## 一、设计目标

### 核心问题
用户从高层意图开始设计（"设计一个储油罐，50m³，0.6MPa"），系统需要：
1. **找到结构方向**——这是哪类已知结构（立式圆筒储罐）
2. **给出完整骨架**——该结构由哪些组件组成（筒体/封头/接管/人孔/支座…）
3. **带出参数关系**——各参数怎么关联（壁厚=f(直径,压力,材料)）
4. **带出约束规则**——适用哪些标准条款（GB 150 §4.3.2）
5. **驱动逐件展开**——每个组件可递归展开为子结构或标准件

### 设计原则
- **DB 保全**：结构化存储保证组件清单完整、参数关系精确
- **RAG 排序**：语义检索提供上下文相关性、标准条文依据
- **机械原理内化**：不只是零件目录，是"为什么这样设计"的工程知识
- **术语块统一**：已知结构 = 高层术语具名块，展开机制复用专利 §B
- **开源共建**：结构库/术语库是行业共性资产，社区贡献覆盖各行业

## 二、数据模型

### ER 概览

```
structure_template (结构模板)
  ├── 1:N → structure_component (组件清单，可嵌套)
  │           ├── ref_template_id → structure_template (子结构引用)
  │           └── ref_part_category → standard_part (标准件引用)
  ├── 1:N → structure_param_def (参数定义)
  │           └── N:1 → structure_principle (参数公式/原理引用)
  ├── 1:N → structure_constraint (约束规则)
  │           └── rag_chunk_tags → RAG (标准条文)
  └── 1:N → structure_assembly_rule (装配规则，组件间连接关系)
```

### 表结构 DDL

```sql
-- ============================================================
-- 1. 结构模板：已知结构的顶层定义（= 高层术语具名块）
-- ============================================================
CREATE TABLE structure_template (
  id              INT PRIMARY KEY AUTO_INCREMENT,
  code            VARCHAR(64)  NOT NULL UNIQUE,  -- 模板编码: VERTICAL_CYLINDER_TANK
  name            VARCHAR(128) NOT NULL,         -- 标准名: 立式圆筒储罐
  aliases         JSON,                           -- 别名: ["储油罐","立式罐"]
  category        VARCHAR(64),                    -- 类目: 压力容器/储运设备/传动装置
  subcategory     VARCHAR(64),                    -- 子类: 储罐/反应釜/减速箱
  description     TEXT,                           -- 结构简述
  standard_ref    VARCHAR(128),                   -- 主标准: GB 150-2011
  applicable_scope TEXT,                          -- 适用范围: "设计压力≤35MPa的钢制压力容器"
  rag_dataset_id  VARCHAR(64),                    -- RAGFlow 数据集 ID（关联知识库）
  expand_template JSON,                           -- 术语块展开模板（运算模板列表，见专利§B）
  status          TINYINT DEFAULT 0,              -- 0=启用 1=退役
  -- 审计列（create_by/create_time/update_by/update_time/create_dept）
);

-- ============================================================
-- 2. 结构组件：结构由哪些部件组成（支持嵌套，即组件本身可以是子结构）
-- ============================================================
CREATE TABLE structure_component (
  id               INT PRIMARY KEY AUTO_INCREMENT,
  template_id      INT NOT NULL,                  -- 所属模板
  parent_id        INT,                           -- 父组件 ID（null=顶层，非 null=子组件）
  name             VARCHAR(128) NOT NULL,         -- 组件名: 筒体/封头/接管/人孔
  component_type   VARCHAR(32) NOT NULL,          -- 见枚举
  ref_template_id  INT,                           -- component_type=sub_structure 时，引用的模板 ID
  ref_part_category VARCHAR(64),                  -- component_type=standard_part 时，零件类目
  quantity_expr    VARCHAR(64),                   -- 数量（可参数化）: "1" / "4" / "@nozzle_count"
  required         TINYINT DEFAULT 1,             -- 1=必需 0=可选
  sort_order       INT DEFAULT 0,                 -- 展开顺序
  principle_note   TEXT,                           -- 机械原理注解（为什么需要这个组件）
  -- 审计列
);

-- component_type 枚举:
-- sub_structure   子结构（递归展开为另一个 structure_template）
-- standard_part   标准件（查 standard_part 表，如法兰/螺栓/垫片）
-- custom_part     定制件（需人工设计，如非标支架）
-- geometry        几何体（直接映射 Q 的 inst 条目，如筒体→cylinder）

-- ============================================================
-- 3. 结构参数定义：该结构类型的设计参数
-- ============================================================
CREATE TABLE structure_param_def (
  id              INT PRIMARY KEY AUTO_INCREMENT,
  template_id     INT NOT NULL,
  param_key       VARCHAR(64) NOT NULL,           -- volume / design_pressure / contents / material
  param_label     VARCHAR(64),                    -- 容积 / 设计压力 / 介质 / 材料
  param_type      VARCHAR(32),                    -- float / int / string / enum / formula
  unit            VARCHAR(32),                    -- m³ / MPa / - / -
  required        TINYINT DEFAULT 1,
  default_value   VARCHAR(128),
  enum_values     JSON,                           -- 枚举可选值: ["Q345R","Q235B","304"]
  validation_rule TEXT,                           -- 校验规则: "0.1~10" 或 JS 表达式
  formula_expr    TEXT,                            -- 计算公式（param_type=formula 时）:
                                                   -- 如壁厚: "P*D/(2*[σ]t*φ-0.5*P)+C"
  formula_refs    JSON,                            -- 公式引用的其他 param_key
  sort_order      INT DEFAULT 0,
  -- 审计列
);

-- ============================================================
-- 4. 结构约束：该结构适用的约束规则（连接 C 约束场）
-- ============================================================
CREATE TABLE structure_constraint (
  id               INT PRIMARY KEY AUTO_INCREMENT,
  template_id      INT NOT NULL,
  constraint_layer VARCHAR(32),                   -- P硬律 / M可行 / V价值 / C_c条件
  target_component VARCHAR(128),                   -- 约束对象: "筒体" / "封头" / "接管-法兰连接"
  rule_type        VARCHAR(32),                    -- dimensional / material / safety / manufacturing
  description      TEXT NOT NULL,                  -- 约束描述: "壁厚不得小于计算值+腐蚀裕量"
  standard_clause  VARCHAR(128),                   -- 标准条款: "GB 150-2011 §4.3.2"
  formula_expr     TEXT,                           -- 约束公式（如需要）: "t >= Pc*Dc/(2*[σ]t*φ-0.5*Pc)+C"
  rag_chunk_tags   JSON,                           -- RAG 检索标签（用于 DB↔RAG 桥接）
  severity         VARCHAR(16) DEFAULT 'hard',     -- hard=违反不可行 / soft=警告
  -- 审计列
);

-- ============================================================
-- 5. 装配规则：组件之间的连接关系（"机械原理"的核心）
-- ============================================================
CREATE TABLE structure_assembly_rule (
  id               INT PRIMARY KEY AUTO_INCREMENT,
  template_id      INT NOT NULL,
  from_component   VARCHAR(128) NOT NULL,          -- 主动件: "接管"
  to_component     VARCHAR(128) NOT NULL,          -- 被动件: "筒体"
  connection_type  VARCHAR(32),                    -- 见枚举
  relation_expr    TEXT,                           -- 位置/尺寸关系表达式
  principle_note   TEXT,                           -- 机械原理: "接管穿过筒体壁，需开孔补强"
  constraint_note  TEXT,                           -- 关联约束: "见 structure_constraint: 开孔补强"
  sort_order       INT DEFAULT 0,
  -- 审计列
);

-- connection_type 枚举:
-- weld            焊接（筒体↔封头环焊缝）
-- flange          法兰连接（接管↔管道，需配对法兰+垫片+螺栓）
-- bolt            螺栓连接（支座↔基础）
-- contact         接触（球体↔底座，rests_on_centered）
-- insert          插入/开孔（接管→筒体，需补强）
-- relative_pos    相对定位（人孔位置避开接管区）
```

## 三、RAG 知识库组织

### 数据集划分

| RAG 数据集 | 内容 | 与 DB 的桥接 |
|---|---|---|
| `kb_standards` | 国标/行标全文（GB 150、GB/T 9119 法兰…） | `structure_constraint.standard_clause` → 切片 tag |
| `kb_textbooks` | 机械设计手册/教材章节 | `structure_template.rag_dataset_id` 关联 |
| `kb_cases` | 设计案例/图纸说明 | `structure_template.aliases` 语义匹配 |
| `kb_materials` | 材料性能/选材指南 | `structure_param_def` material 枚举验证 |

### DB↔RAG 桥接机制

```
DB 记录                                RAG 切片
─────────                              ─────────
structure_template                     kb_textbooks 切片
  .rag_dataset_id ──────────────────→  metadata: {dataset_id, template_code}
                                          
structure_constraint                   kb_standards 切片
  .standard_clause = "GB 150 §4.3.2"  metadata: {standard, clause}
  .rag_chunk_tags ──────────────────→  tags: ["GB150","壁厚","筒体"]
                                          
structure_param_def                    kb_textbooks 切片
  .formula_expr                        metadata: {param_key, template_code}
```

**桥接策略**：DB 记录存 `rag_chunk_tags`/`standard_clause` 作为检索锚点，RAG 切片 metadata 存 `template_code`/`standard` 作为回查键。双向可查。

## 四、融合检索流程

### 场景：用户说"设计一个储油罐，柴油，50m³，0.6MPa"

```
Step 1: 术语归一（知音 L1-L2）
  "储油罐" → DB mech_term 精确匹配 → 命中 standard_form="立式圆筒储罐"
  别名匹配: "储油罐"∈ structure_template.aliases
  
Step 2: 结构检索（DB 保全 + RAG 排序）
  DB:  SELECT * FROM structure_template 
       WHERE name LIKE '%储油%' OR JSON_CONTAINS(aliases, '"储油罐"')
       → 命中 template: VERTICAL_CYLINDER_TANK
  RAG: 在 kb_textbooks + kb_cases 中检索 "储油罐 柴油 50m³ 0.6MPa"
       → 返回相关章节/案例（排序依据）

Step 3: 骨架提取（DB 全量召回组件）
  DB:  SELECT * FROM structure_component 
       WHERE template_id=X ORDER BY sort_order
       → 完整组件清单: 筒体/封头/接管×N/人孔/支座/安全阀/液位计
       
Step 4: 参数填充（DB 公式 + RAG 依据）
  DB:  SELECT * FROM structure_param_def WHERE template_id=X
       → 参数定义: volume=50, pressure=0.6, contents=柴油, material=?
       formula: 壁厚 = P*D/(2*[σ]t*φ-0.5*P)+C  ← 需材料参数
  RAG: 检索 "Q345R 材料性能 GB 150" → [σ]t 值
       → 代入公式 → 壁厚 ≈ 12mm
       
Step 5: 约束装配（DB 规则 + RAG 条文）
  DB:  SELECT * FROM structure_constraint WHERE template_id=X
       → 约束清单: 壁厚≥计算值+腐蚀裕量 / 封头壁厚≥筒体壁厚×0.8 / ...
  RAG: 按 rag_chunk_tags 检索标准条文 → 约束依据

Step 6: 装配关系（DB 规则）
  DB:  SELECT * FROM structure_assembly_rule WHERE template_id=X
       → 装配清单: 筒体↔封头=焊接 / 接管→筒体=插入补强 / 支座↔基础=螺栓
```

## 五、与架构各层的接口

```
                    ┌──────────────────┐
  用户话 ──────────→│ 知音 L1-L2 词表   │ 术语归一
                    └────────┬─────────┘
                             │ 标准术语
                    ┌────────▼─────────┐
                    │ 已知结构知识库    │ DB 保全 + RAG 排序
                    │ (本文档定义)      │ → 输出结构 JSON
                    └────────┬─────────┘
                             │ 结构 JSON
                    ┌────────▼─────────┐
                    │ Anvil LLM        │ 翻译为 ΔQ（add inst/param/feat/rel）
                    └────────┬─────────┘
                             │ ΔQ
                    ┌────────▼─────────┐
                    │ Q 需求矩阵        │ Q' = Q + ΔQ
                    └────────┬─────────┘
                             │ Q
                    ┌────────▼─────────┐
                    │ Primordium 内核   │ Σ驱动 → Π分解 → Δ调度 → Ω执行 → S
                    └──────────────────┘
```

**接口定义**：
- 知音 → 已知结构库：标准术语 + 用户参数 → 检索请求
- 已知结构库 → Anvil：结构 JSON（如上示例）
- 已知结构库 → 约束场：`structure_constraint` 表为 C 约束场提供约束规则来源
- 已知结构库 → Q：不直接写 Q（通过 Anvil 翻译为 ΔQ）

## 七、开源共建模型

```
开源仓库（知识库内容）                    私有仓库（求解引擎）
────────────────────                      ────────────────────
structure_template 数据          ←→       Primordium 内核（ΣΠΔΩ）
mech_term 术语数据                        Anvil 翻译层
standard_part 标准件数据                    C 约束场
RAG 切片（标准/教材/案例）

社区贡献:                                 不开放:
- 新行业结构模板（化工/汽车/航空…）         - ΔQ 代数实现
- 方言/行话术语                            - 约束求解器
- 行业标准切片                             - 异构调度
- 设计案例
```

**贡献流程**：模板经 RV 评审矩阵审核 → 测试通过 → 合并入库。术语块展开机制（专利保护）是引擎，模板内容（开源共建）是燃料。
