# Primordium · 元初

> **位置**：`DesignTool/Primordium/`（与 frontend / Anvil / SketchService / ParamDerive 平级）
> **定位**：「从具象到抽象」理论课题的知识库与公理档案。理论本身是域无关的——它研究的是「可靠构建」的普遍结构。机械 AI 约束场是其当前首要案例方向
> **命名**：Primordium（拉丁语，器官原基）——一切结构从它涌现。中文「元初」：元要素之初
> **性质**：不是软件工具，是课题的理论档案——收录从假说到元构建的全部原始论证

## 地位（2026-09-02 定调）

在 DesignTool 整机中，Primordium 是**唯一的框架层**——数学内核与理论本体，居两壳之间：

```
frontend(交互壳) → 知音(语义归一) → Anvil(翻译壳, LLM) →【Primordium 框架层（Ω 执行层在此）】→ CADService(FreeCAD 工具载体, 可替换)
```

**所辖五物**（他层皆不得僭越）：

| 所辖 | 是什么 |
|------|--------|
| Q / S 双矩阵账本 | 需求与结果的唯一权威表示；ΔQ 加法器是 Q 的唯一写入通道 |
| 内核四件套 Σ Π Δ Ω | 无 LLM·无概率·可复算——状态全在 Q/S 账本，内核只带转移逻辑；同 Q 必得同 S |
| τ 工具面 | 一切跨层交互的唯一通道，层层是工具、层层可独立测试 |
| 文法与字母表 | 可穷举词表/语义数值映射的单一来源（grammar → vocabulary.json） |
| 硬约束判定 | 𝒫/𝒞ₘ 的 PASS/VIOLATION 二值裁决权，任何算力与模型不得代行 |

**边界三条**：Anvil/知音只是壳（翻译与归一，可换模型可换 RAG）；CADService 只是手（FreeCAD 载体，可替换）；**核壳之分**——四肢不得指挥心脏（资料 008）。框架可复用于任何"在硬约束下求必然解"的领域，机械设计只是首要案例。

## 理论与工具的关系（2026-08 定稿）

本课题不是与工具分离的学术研究——**理论活在工具里，通过工具渐进、迭代地证明价值**：

```
Primordium(理论,持续演化)
  ↓ 形式化为
设计原语体系(原语注册表+约束规则+术语语义)= 理论的当前可执行快照
  ↓ 被消费/被验证
Anvil(验证场):每次真实设计会话 ①使用当前理论 ②暴露理论缺陷
              (submit_gap 能力缺口回流)③驱动理论修订
```

- Anvil 现有原语/约束规则(通孔深度<壁厚等)/术语语义(mech_terms
  的 geometry/modeling 字段)是本理论的初级形态
- 设计循环(submit_gap → 后端补原语 → 审阅 → 重做)=「理论缺陷发现→
  理论修订」的工程化体现
- 宣传理论体系时,Anvil 能直观演示其正确性与价值

## 物理根基

这不是一套飘在符号层上的理论架构。它构建于两项最基本的确定性之上：

- **立体几何**——空间不是像素网格，不是 token 序列。空间有体积、有方向、有不可穿越的边界。理论承认空间的客观性，而非将其降维为信号去统计。
- **物理**——守恒律、力学平衡、热力学第二定律不是「训练数据中的模式」，是不可违逆的硬约束。在 Primordium 的框架里，物理不是后置的校验环节，是构建时的第一性输入。

这恰恰是 Primordium 与当前生成式 AI 路线的根本分野：生成式 AI 的答案来自统计关联，没有物理——它不知道「这个螺栓放这里会不会断」。Primordium 的目标不是生成更像的东西，而是**在硬约束下求出必然解**。

> 参见资料 017：CV 的数学是「看」的数学（卷积），LLM 的数学是「说」的数学（注意力），机械 AI 的数学是「在」的数学（变分几何）。「在」不是空话——它的根基就是立体几何 + 物理。

## 课题四件核心资产

1. **层级约束的认知框架**——任何复杂系统的可靠构建，都依赖不可再分的元约束优先于次级约束的精密语法：硬律→可行→价值，逐层嵌套。AI 理解宗法这一案例是触发本认知的原动力，宗法本身不是本理论研究的内容
2. **LLM 的结构性无能**——架构天生不擅长符号链式推演、长程状态保持、硬约束遵守；不是知识不够
3. **核壳之分**——旧壳（CAD/CAE/LLM）做终端展现，新核（约束场引擎）从「元」重构；旧器新魂
4. **假说→证明→元构建**——数学道统而非工程迭代；定理般的必然性，不是统计意义上的大概率

## 约束的狭义定义

<!-- ref: R-001, sources: S-001, S-002 -->

本课题中的「约束」取狭义：**客观存在的、可被独立实验证伪的不可违逆性条件**。它来自世界的结构本身（物理的、几何的、生物力学的），不来自人的设定。

| | 狭义约束（Constraint） | 社会制度 / 约定（Institution / Convention） |
|:---|:-----|:-----|
| 来源 | 世界的结构 | 人的同意 |
| 验证 | 实验——违反则物理世界驳回 | 协商——违反则人说「不许」 |
| 可证伪性 | 可被独立观察推翻 | 不可证伪——它是规定，不是陈述 |
| 变更方式 | 不可变更，只能被发现 | 可协商变更 |
| 例 | 能量守恒、拔模斜度为零无法脱模 | 宗法辈分、法律条文、安全系数取 1.5 |

社会制度（宗法、法律、行业标准）同样是层级嵌套的不可违逆结构——正因如此，AI 理解宗法这一事件是触发认知的原动力：宗法制度本身的层级结构展示了「硬律→可行→价值」的精密约束语法。但社会制度的合法性来自人的同意和执行，不是来自物理世界的驳回机制。Primordium 理论的对象是**狭义约束**——宗法是启发来源，不是理论内容。

这里存在一个辩证统一，消除表面上的矛盾。社会制度可以在两个认识论层级上被考察：

| 层级 | 取径 | 判断 | 例 |
|:---|:-----|:-----|:-----|
| **作为规范** | 「你应该怎么做」——规范性的、作用于当下的 | 不属于狭义约束，排除在框架内容之外 | 「大宗不可迁」作为应遵守的礼制 |
| **作为事实** | 「历史上客观上是什么样」——描述性的、已固化的 | 属于狭义约束——可被《仪礼》原文独立验证 | 「大宗不可迁」作为宗法制度中一条客观存在的规则结构 |

同一句话「大宗不可迁」，在第一个层级是向你发号施令的规范，在第二个层级是躺在典籍中等着被核查的历史事实。你反复强调排除宗法作为框架内容——排除的是第一层（不让规范僭越为 𝒞 算子的约束来源）。但你保留它作为启发案例——用的是第二层（宗法作为一个客观存在过的历史实体，其层级约束语法是可被独立验证的认知素材）。二者不矛盾。

这个区分同样解释了亲属推算引擎的双重身份：称谓规则（「堂祖父叫什么」）本身是规范——它属于第二层，作为已固化的历史事实被形式化验证；但引擎的**逻辑结构**（消歧→世代差→查表）是域无关的——它可以映射到任何需要「从关系网络做形式化推演」的约束场景。

𝒞 算子的三层（𝒫 硬律 / ℳ 可行 / 𝒱 价值）必须经得起这条标准的检验：每一层都必须是狭义约束。价值场的客观性不在偏好本身，而在偏好的成因链——追问下去，偏好总是硬律或可行边界的投影（重量<20kg 是因为楼板承重、老人推力、运输成本非线性拐点，这些底层的可证伪约束规定了偏好的可行域）。

> 约束的严格数学形式化（𝒞ₚ / 𝒞ₘ / 𝒞ᵥ 的集合论定义、约束势 Φ、梯度流 dx/dt = −∇Φ）见 [理论根基.md §2.1.1](理论根基.md#211-严格形式化)。

## 公理系统（三层）

> 以下公理的表述以机械设计为当前案例方向；四元与三元组本身是域无关的，可映射到任何需要「在硬约束下求必然解」的领域。

**本体论四元**（世界由什么构成，资料 007）：

| 元 | 本质（通用） | 以机械设计为例 |
|:---|:-----|:-----|
| 物质元 | 基底实体的存在及其固有属性 | 材料的存在及其物理属性 |
| 能量元 | 因果效力的传递与转化 | 力、热、电磁的传递与转化 |
| 信息元 | 实体间的关联结构与差异度量 | 几何形体的拓扑关系与精度 |
| 约束元 | 硬律、可行边界、价值指向的不可违逆性 | 物理定律、工艺极限、价值偏好 |

**动力学四元公理**（世界如何运动，资料 015）：

1. **边界即命运**——设计的本质不是结构，是约束的落点
2. **相变即涌现**——好设计与坏设计之间没有渐变，只有拓扑相变
3. **耦合即牢笼**——硬律-可行-价值，任何一头松动则全场重锁
4. **收敛由场定**——设计必须收敛，但收敛的目标由场决定

**数学基础三元组**（怎么算，资料 017）：

| 支柱 | 解决的问题 |
|:-----|:-----------|
| 微分几何 | 设计空间的流形结构——「所有可能的结构」是弯曲的高维曲面 |
| 变分法/泛函分析 | 结构是泛函取极值时「自然析出」的稳态解，不是搜出来的 |
| 代数拓扑 | 孔洞的生成与合并、结构的拓扑相变（同调/持续同调） |

> 核心算子：𝒞 = 𝒫 ⊕ ℳ ⊕ 𝒱（约束场算子 = 硬律场 ⊕ 可行场 ⊕ 价值场）。以机械设计为例：物理场 ⊕ 制造场 ⊕ 价值场。作用方式不是前向传播，而是收敛到稳态。

## 架构主张

**三场耦合**（资料 006）：硬律场（不可违逆的域内定律）× 可行场（实现路径的势垒）× 价值场（偏好度量），统一为解空间的曲率；结构是场中的测地线，被场的几何决定，而非被搜索出来。以机械设计为例：物理场（Navier-Stokes/弹性力学）× 制造场（铸造充型/切削力）× 价值场（成本/重量/寿命）。

**四层混合**（资料 004-005）：交互层（LLM 仅限翻译，不决策）/ 知识层（KG 约束与记忆）/ 计算层（引擎）/ 验证层（形式化检查）。

**核壳运行图**（资料 008）：心脏（约束场引擎）泵血，四肢（现有工具/平台/模型）只是终端表现——四肢不得指挥心脏。

## 三条原则（继承自 DesignTool 宪章）

1. 无意取代已有成熟工具，尤其开源工具——它们做壳（FreeCAD/Neo4j/LLM 皆为终端）
2. 表达更多信息、语义、意图、抽象——核（约束场/推算规则）自构
3. 便于 AI 处理、理解、加工——LLM 仅限翻译，不决策

## 里程碑与止损（资料 012）

> 以下以机械设计为案例方向。

- **1 年**：三场耦合数学假说 + 形式化表述
- **3 年**：极简案例验证（悬臂梁拓扑优化）
- **5 年**：场引擎内核 V0.1（二维）
- **10 年**：对接工业级 CAD/CAE 壳层

| 死法 | 止损点 |
|:-----|:-------|
| 数学死 | 第 2 年：核心泛函存在性证不出 → 转弱约束版本 |
| 工程死 | 第 5 年：V0.1 算不动 → 退符号+数值混合架构 |
| 身体死 | 随时：移交/开源/未完成的祖庙供后人续修——传承本身就是完成 |
