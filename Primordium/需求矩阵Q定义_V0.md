## 一、核心设计原则：双重视角，一个对象

```
                    ┌─────────────────────┐
  用户话 ──Anvil──► │   需求矩阵 Q          │ ──Π──► 任务 DAG（CPU/NPU 标注）
  （ΔQ 增量落账）     │  条目 + 属性 + 代数   │         │
                    └─────────────────────┘         ▼
                          ▲                      Ω 执行 → S
        回显视图（表述侧）    │    规划视图（编译侧）
        "将创建:Ø100空心球…"  │    task(inst:ball)→CSG@CPU
```

**两条硬性要求：**

| 视角 | 要求 | 不满足的后果 |
|---|---|---|
| 需求表述 | 每个条目**可回显**（结构化中文摘要给用户确认）、**可溯源**（指令号 ↔ Anvil design_log.seq 对接，沿用既有实现） | 用户无法审校翻译，错译静默潜伏 |
| 计算规划 | 每个条目**可规划**——映射到 ≥1 个任务，或显式声明"无需计算" | 出现"说得出但算不了"的条目 = 静默丢失（正是历次事故的根源形态） |

**双视角不变量**：`表述完整性 ⇔ 规划覆盖`。

**ΔQ 加法器**：Q 的唯一写入通道，执行 `Q′ = Q + ΔQ`（校验通过才落账，溯源 Φsrc 记指令号）。设计指令被翻译为 ΔQ，经加法器对 Q 施加 + 运算——这是指令作用于需求的唯一方式。
加法器算子三型：**增**（新增条目）/ **删**（移除条目，即逆元 −ΔQ，按 Φsrc 定位）/ **改**（更新条目字段，即 改回型逆元）——型不同，通道唯一，校验与溯源规则相同。代数保证：每个 ΔQ 存在逆元（增↔删、改↔改回），故回滚 = Q + (−ΔQᵢ)，"−"只是记法简写——**全系统只有一个运算：+**。
条目规划不出任务 ≠ 忽略它——那是**能力缺口**，走 request_tool/EVOLUTION 流程立单，永不静默。

## 二、条目模型（统一 schema）

Q 的最小单位是**条目（entry）**，不分表（属性标识归类，不影响结构表示）：

```json
{
  "id": "q-000042",
  "family": "rel",                          // 条目族（见 §三）
  "refs": ["ball", "base"],                 // 关联体/条目
  "value": { "rel": "rests_on_centered" },  // 族内字段（见 §三）
  "attrs": {
    "authority": "strong",                  // strong=Q1 / derived=Q2
    "dimension": "geom",                    // geom|phys|motion|manuf|intent|org
    "source": "inst#7",                     // 指令号 / 规范化规则号
    "status": "active",                     // active | stale(待重解)
    "confirmed": false                      // Q2 经用户确认升格后置 true
  },
  "plan_hint": {                            // 可选；Π 拥有权威推导权
    "ops": ["assemble", "solve"],           // 提示参与的任务类型
    "batch_key": null                       // 同 key 可合批（NPU）
  }
}
```

- **指称与引用（2026-09-02 定调，类比面向对象）**：id 是条目的唯一指称，**取值为单调递增整数**（矩阵行号；"q-42" 仅为显示格式，存储与计算一律用数）——为矩阵计算预留：I/Θ/F/S 的行即按此行号对齐，retired 行掩零/遮蔽，行号永不复用（复用=行语义漂移，等价 use-after-free）。refs 字段是条目间的**引用**：param/feat 引用 inst，rel 引用体对，类比对象的组合持有。条目删除即"析构"，指称进退役名录（retired，记删除时版本），设计全程只认指称，不因增删而漂移
- **符号→数的映射边界**：LLM 翻译 ΔQ 时只说符号（体名/kind 词表词），**永不发明数字指称**——符号→数的映射由加法器/词表在落账时确定性完成（同 语义数值映射定义 的枚举 id 规则）；语义面开放、数值面封闭在此闭合
- 表述侧消费：`family + value + refs` → 回显摘要
- 规划侧消费：`family + value + attrs + refs` → 任务生成、依赖推导、target 标注
- Q 的代数（ΔQ 三型原语、Q1/Q2 权威、apply 两段式）见《DesignTool架构定义_V0.md》§一，本文不重复

## 二.5 翻译工效：表述侧为 LLM「准确、快速」而设的硬规则

Q 的 schema 不是中立的数据格式——它的每一处设计都在决定 LLM 错译率和翻译成本。

### 准确（压缩出错空间）

| 规则 | 内容 | 针对的历史事故 |
|---|---|---|
| 1. 必填最小集 | 每族字段三级：**required**（用户必说）/ **optional**（可说）/ **system**（禁止 LLM 写——Q2 规范化补） | LLM 编造 sphere 的 outer_radius/inner_radius（2026-09-01） |
| 2. 一词一义 | kind/op/rel 全枚举（清单=《语义数值映射定义_V0.md》§二/§四），非法值立即 422；方言/俗称先经知音四级漏斗归一，行话（盲孔/法兰）走**术语块** ΔQ_block 查表，LLM 不做近义词猜谜 | "空心球"→shell_box 硬凑 |
| 3. 反馈精确定位 | 422 错误必须落到 op 序号+字段名+类型建议，重译有方向不瞎试 | 打回后乱改 |
| 4. 例句与 schema 同源 | 词表注入 prompt（GET /api/grammar 已实现）+ 每族 2~3 条标准例句，同源更新永不脱节 | prompt 手写清单脱节事故 |

### 快速（压缩往返与 token）

| 规则 | 内容 |
|---|---|
| 5. 增量翻译 | 只译 ΔQ 不重述全局："改成 Ø120" = 一个 upd op（Q 的增量语义直接省 token） |
| 6. 块引用压缩 | 行话 = block 名+参数，一条 ΔQ_block 抵几十条 entry |
| 7. 输出最小化 | 字段名短、optional 可省、**禁写 plan_hint**（规划提示由 Π 推导，LLM 填了也会被覆盖） |
| 8. 机械校验前置 + 缓存 | schema 校验毫秒级先跑（不烧 token）；相同/相似指令命中历史 ΔQ 缓存或知音句对（RAG）直接复用 |

### 翻译质量验收指标（金测试集跑分，蓝图 §五.5 度量侧）

- **一次译过率**：首轮无 422 且回显确认通过的比例（目标 ≥90%，现有 glm 弱翻译基线待测）
- **平均往返次数**：≤ 1.2（打回重译的代价直接反映在此）
- **单指令翻译 token 上限**：块引用 + 增量翻译后设硬上限，超限视为 schema 设计问题而非 LLM 问题

## 三、矩阵族定义（表述语义 × 规划映射）

每族按同一模板定义：**表述语义**（捕捉用户的什么）→ 条目字段 → **规划映射**（生成什么任务、依赖来源、默认 target）。

### 3.1 inst 实例族 —— "有哪些体"

| | 内容 |
|---|---|
| 表述 | "一个空心球、一块底板" → 体的存在声明 |
| 字段 | `{ kind: sphere|cylinder|box, name, anchor: center|bottom_center }` |
| 规划映射 | 生成 **体元求值任务**（几何构造原语）：`task_csg(kind, params)` |
| 依赖 | 无（DAG 根节点）；锚点语义供坐标解算引用 |

### 3.2 param 参数族 —— "多大/多厚"

| | 内容 |
|---|---|
| 表述 | Ø100、壁厚 20 → 体/算子的数值 |
| 字段 | `{ target_entry, key, value 或 interval:[lo,hi] }`（interval = 形状意图，规格可换档） |
| 规划映射 | 定值 → 并入所属体的 CSG 任务参数；**区间 → 批量扫描任务（张量核/NPU）**：同稀疏模式 A·X=B(θ)，θ∈区间端点/采样 |
| 依赖 | 挂在 target_entry 之后 |

### 3.3 feat 特征族 —— "做什么变形"

| | 内容 |
|---|---|
| 表述 | "空心"→shell(t)；"均布 4 孔"→linear_pattern(n,d) |
| 字段 | `{ op, t|n|d…, base_entry }` |
| 规划映射 | 生成**算子演算任务**：shell → [内腔体求值 + subtract]（几何原语）；pattern 大 n → 批量任务（张量核/NPU） |
| 依赖 | base_entry 之后（算子依赖） |

### 3.4 rel 关系族 —— "谁相对谁在哪"

| | 内容 |
|---|---|
| 表述 | "置于底座中心"→rests_on_centered；"同轴"→coaxial_z |
| 字段 | `{ rel, a, b, params(如 gap g) }` |
| 规划映射 | 每条 → **方程模板行**（L2）汇入装配 A；全族装配完成 → **稀疏求解 + 零空间诊断任务**（CPU；大规模 CG→张量核/NPU） |
| 依赖 | **数据依赖的来源**：a rests_on b ⇒ b 的位姿任务先于 a 的（拓扑序由 rel 图导出） |

### 3.5 anchor 锚定族 —— "坐标系从哪开始"（𝒞_c）

| | 内容 |
|---|---|
| 表述 | 用户说"以底板左下角为原点"；或系统规范化补默认（Q2） |
| 字段 | `{ entry, dof: [Tx,Ty,Tz…], value }` |
| 规划映射 | 求解任务的边界条件输入；决定适定性（rank 诊断的基准） |
| 依赖 | 求解任务之前 |

### 3.6 mat / load / env 物理族 —— "什么材料、扛多少、什么工况"

| | 内容 |
|---|---|
| 表述 | "Q235"“承重 500kg"“工作温度 -20~60℃" |
| 字段 | `M̂[body, prop]` / `L[body, 6分量+作用点]` / `E[工况区间]` |
| 规划映射 | 按**角色**挂验证器任务（工程校核原语（闭式公式）：板承重/销剪/梁弯…）；V3 场求解（张量核/NPU）。角色未知 → 报能力缺口 |
| 依赖 | 几何+位姿完成之后（验证依赖） |

### 3.7 manuf / intent / group 组织族 —— "造得出吗/别丢了我想要的/怎么分组"

| | 内容 |
|---|---|
| 表述 | Cₘ 工艺极限；"孔位留调节量"（调义=保护零空间方向 v）；装配组 |
| 规划映射 | Cₘ → 不等式判定任务；意图 → **漂移检测任务**（每次 ΔQ 落账后自动追加：v ∈ N(A_new)?）；分组 → 装配序（拓扑） |
| 依赖 | 判定/检测类任务最后；意图检测挂在每次增量后 |

> 全族通用规则：**target 标注由 Π 按规模阈值与合批检测裁决**（§3.2/3.3 的批量形态是仅有的默认 NPU 任务；单件设计 V1 全 CPU）。

## 四、规划视图：Q → 任务 DAG 的编译规则（Π 消费规范）

```
compile(Q) → DAG:
  1. 任务生成：逐条目按 §三 映射表展开（entry → 1..n 个 task）
  2. 依赖合成：三类边
     a. 数据依赖（rel 图拓扑序）
     b. 算子依赖（feat/布尔在 base 之后）
     c. 验证依赖（mat/load/manuf/intent 在几何+位姿之后）
  3. 异构标注：逐 task 按规模阈值 + batch_key 合批检测 → target=CPU|NPU
  4. 诊断附着：求解任务产出 rank/DOF → 回写 Q 诊断字段；intent 检测产出 INTENT_LOST 事件
  5. 预览任务（WYSIWYG）：每次 ΔQ 落账自动追加——增量编译 stale 子图→快速求解→轻量网格；欠定部分占位+高亮，不猜不空白。**产物落独立目录（cad/{step_id}/）并记 design_log——维持 Anvil 每指令一目录的现行模式，随时可查看**
```

**Q 侧必须为编译提供的元数据**（这就是"考虑计算规划"的具体含义）：
1. 每条目的 family/refs/value 结构化（语义任务化的输入）
2. rel 图（依赖推导的输入）
3. 区间/批量标记（合批检测的输入）
4. 规模提示（体数、约束数、区间宽 → target 决策输入）
5. stale 标记（ΔQ 落账后哪些条目需要重算——增量重解不Whole重放）

## 五、诊断与状态字段（Q 自身的健康度）

| 字段 | 含义 | 来源 |
|---|---|---|
| `Q.wellposed` | rank/DOF 诊断：适定/欠定(附自由度清单)/冲突(附行号) | 求解任务回写 |
| `entry.status` | active / stale（关联变更后待重算） | ΔQ apply 回写 |
| `Q.gaps[]` | 规划覆盖失败的能力缺口清单 | compile 回写 → EVOLUTION |
| `Q.intent_locks[]` | 被保护方向清单 | 调义条目落账时建立 |
| `S.verify` | 验算记录（异源算法 + 残差/区间界） | 验算原语回写 |
| `Q.unreachable` | 不可达证明链（最小冲突集） | 区间收缩/过定检测 |

## 七、验收用例（空心球三指令 → Q → DAG）

| 指令 | ΔQ 落账（family/value/authority） | 生成的任务（Π 编译） |
|---|---|---|
| "空心球 Ø100 壁厚20，下置 100×100×20 底板，球置于底板中心" | inst(sphere r=50)+feat(shell 20)+inst(box)+rel(rests_on_centered)+anchor(Q2 默认) | task_csg(球) task_csg(板) task_shell(球) task_assemble+solve —— 全 CPU |
| "底座承受 500kg 静载" | load(base, -Z 4905N) + mat(Q235, Q2 默认材料库) | task_verify(板承重校核, L2) 依赖几何+位姿 |
| "球规格以后可能换 Ø80~120" | Θ̃[球,r]=[40,60]（区间·意图） | task_batch(A·X=B(θ), θ∈端点, L3/NPU) + task_intent(区间可行性) |

验收断言：① 每条目都有 ≥1 任务（无静默丢失）② DAG 依赖与物理常识一致（板先于球）③ 回显可让用户拦截错译 ④ 区间任务落 NPU 批量。

## 八、实现注记

- 存储：单张 entry 表（JSON 字段 + 属性列）+ 版本链日志；不按族分表（结构表示恒定）
- **账本唯一，快照在外**：Q 活账本在 Primordium 仅一份；Φsrc 溯源与 Q 快照由 Anvil 持有——快照/加载 = 回滚、分支、what-if 的基础设施（加载即经 ΔQ 加法器重放或整体置换，仍走唯一写入通道）
- Π 的 compile() 是纯函数：compile(Q) 幂等；ΔQ 增量编译（只编译 stale 子图）为 V1 优化项
- 与 8103 的关系：grammar（合法性）→ 本定义（Q 模型）→ resolver compile（DAG）→ compose（执行）
