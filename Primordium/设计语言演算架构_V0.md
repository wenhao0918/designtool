# 设计语言演算架构 V0 —— 结果是算出来的

> 版本: V0.1
> 日期: 2026-09-01
> 上位文档: 《技术框架规划.md》（约束场AI系统架构）
> 适用范围: DesignTool 建模链路（Anvil / PrimitiveService / CADService）

---

## 一、背景与教训（为什么必须改）

2026-09-01 "模型能力测试"项目两次事故的完整证据链：

| 轮次 | 系统状态 | LLM 行为 | 结果 |
|---|---|---|---|
| 第一次 | prompt 手写名录缺 sphere | 以为没有球原语 | 拿 shell_box 硬凑"空心球" |
| 第二次 | 17 原语全量注入 + 强制查清单 | **看到清单后仍选 shell_box**，且先编造 sphere 不存在的参数 | 错误结果自信交付 |

结论：**"空心球→选哪个原语"是语义联想，联想的本质是概率。**
修 prompt、加护栏只能提高概率，不能把概率变成必然。只要建模决策放在 LLM 里，
这类错误就会以新的形态复发。这正是上位文档第一公理的否定式表述：
*用统计归纳替代物理演绎 = 架构性错误*。

## 二、第一性目标

> **结果是算出来的。**

检验标准——换一个需求，系统不需要任何新知识：

```
"空心球 Ø100 壁厚20"                      "空心圆筒 Ø60×高80 壁厚8"
  球体 = { x : |x−O| ≤ r }                 圆筒 = { x²+y² ≤ r², 0 ≤ z ≤ h }
  壳(体,t) = 体 ∖ 体.offset(−t)             （同一条壳算子定义）
  S外=球(50), S内=球(50−20)=球(30)          C外=圆筒(30,80), C内=圆筒(22,80)
  材料 = S外 ∖ S内   ← 布尔演算             材料 = C外 ∖ C内  ← 直接算出
```

没有一条是查表，全部是**定义 + 算子 + 方程**的演算。
"算出来的"与"查出来的"分水岭：新需求是否需要新知识。

## 三、架构：词汇极小，演算无限

设计语言文法 = 四张冻结的表。组合空间无限，词汇全部收口。

### 3.1 体元表（数学定义，非库名）

| kind | 数学定义 | 锚点 | 参数 |
|---|---|---|---|
| sphere | {x: \|x−O\| ≤ r} | 球心 | r |
| cylinder | {x²+y²≤r², 0≤z≤h} | 底面中心 | r, h |
| box | [0,L]×[0,W]×[0,H] | 底面中心 | L, W, H |

### 3.2 特征算子表（通用数学算子，作用在任何体上）

| op | 定义 | 说明 |
|---|---|---|
| shell(t) | 体 ∖ 体.offset(−t) | 通用掏壳；一次实现，球/筒/盒全部获得空心能力 |
| linear_pattern(n, d) | 体⊕(k·d, k=0..n−1) | 阵列 |
| fillet(r) | 边缘变半径滚动球面 | V1 |
| mirror(plane) | 体 ∪ σ(体) | V1 |

### 3.3 关系谓词表（约束方程，解出位姿）

| rel | 方程（闭式解） |
|---|---|
| rests_on_centered(a,b) | z: a.bottom = b.top；xy: a.center = b.center |
| coaxial_z(a,b) | a.axis_xy = b.axis_xy |
| gap_z(a,b,g) | a.bottom = b.top + g |
| side_by_side_x(a,b) | a.xmin = b.xmax |

### 3.4 判定（无概率）

𝒫/𝒞ₘ 不等式只输出 **PASS / VIOLATION**（违例附 violated_constraint）。
例: shell.t < r（壳不可逾越母体）、rests_on 不得体积干涉。

### 3.5 句子结构（LLM 的唯一合法输出）

```json
{
  "lang": "dsl.v0",
  "bodies": [
    {"id": "ball", "kind": "sphere", "r": 50,
     "features": [{"op": "shell", "t": 20}]},
    {"id": "base", "kind": "box", "L": 100, "W": 100, "H": 20}
  ],
  "relations": [
    {"rel": "rests_on_centered", "a": "ball", "b": "base"}
  ]
}
```

## 四、模块分工（谁做什么，边界即铁律）

层级关系（定调 2026-09-01）：**前端 → Anvil → Primordium → 执行内核**。
Primordium 是设计语言与演算框架层（文法/矩阵/约束/术语），PrimitiveService(8103)
只是它当前的服务化载体（MCP/HTTP 接口），框架与载体分离——框架可复用，载体可替换。

```
┌──────────────────────────────┐
│ 前端 Frontend                 │ 用户交互:草图/回显确认/设计日志/3D查看/欠定自由度决策
├──────────────────────────────┤    │ 用户话                ▲ 回述/VIOLATION/结构化摘要
│ Anvil（应用层·壳层翻译官）      │    ▼ LLM 翻译:用户话→句子JSON; 会话编排; 调计算工具
├──────────────────────────────┤    │ 句子JSON(MCP/HTTP)     │ 演算结果/轨迹/判定
│ Primordium（框架层）           │ ◄──┘ 设计语言文法 grammar      │
│  载体 = PrimitiveService 8103 │    矩阵演算 resolver(体元→算子→关系方程→坐标)
│                               │    约束判定 constraints(𝒫/𝒞ₘ PASS门禁)
│                               │    术语块词典 / 矩阵表示(V1)
├──────────────────────────────┤    │ parts/joints(MCP compose)
│ CADService（执行内核）8102     │ ▼ FreeCAD → STEP/STL
└──────────────────────────────┘
```

| 模块 | 职责 | **禁止事项** |
|---|---|---|
| **前端** | 交互/回显确认/设计日志/3D 查看；欠定自由度交用户决策 | 不做翻译，不做几何 |
| **Anvil Agent（LLM）** | 把用户话翻译成文法句子；调用 Primordium 计算工具（MCP）；向用户回述演算结果与 VIOLATION | **禁止**选原语、算坐标、决定建模方法；VIOLATION 只许转述不许自行换方案重试 |
| **Primordium.grammar** | 句子合法性判定：词汇∈表、结构合文法、参数完备。不合法→打回（LLM 重译），没有第三种结果 | 不做几何计算 |
| **Primordium.resolver** | 体元求值→算子代数→关系方程→坐标解算；输出 parts/joints + 全程演算轨迹（每步可追溯） | 不调用 LLM；不含 if 意义上的"设计决策" |
| **Primordium.constraints** | 𝒫/𝒞ₘ 不等式判定，PASS/VIOLATION | 不输出置信度/推荐 |
| **CADService** | FreeCAD 执行内核，产出 STEP/STL | 不理解语义 |
| **用户（经前端确认）** | 翻译歧义（"装在上面"=贴合还是间隙？）由结构化回显显式交还用户确认 | 系统不准替用户猜 |

**MCP 调用关系**（与用户定义一致：LLM 解析出参数后调用计算工具）：
- PrimitiveService 8103 = MCP Server，暴露 `resolve_design_intent(sentence)` 计算工具
- Anvil Agent 的 LLM 唯一建模动作 = 调用该工具（MCP/HTTP 同构）
- 8103 内部再以 MCP/HTTP 调 CADService compose —— 全链工具化、每层可独立测试

**词汇表单一事实源**：四张表只存在于 grammar.py，prompt 里的词汇说明由
`GET /api/grammar` 动态注入（沿用"名录跟注册表走"的教训，杜绝手写脱节）。

## 五、空心球完整演算（验收用例，全程零 recipe、零概率）

```
输入句子: bodies=[ball(sphere r=50, shell t=20), base(box 100×100×20)]
          relations=[rests_on_centered(ball, base)]

① 体元求值:  ball → 球(r=50), 锚=球心;  base → 盒(100,100,20), 锚=底面中心
② 算子代数:  ball.shell(20) → S内 = 球(50−20=30)      ← 30 是减出来的
            → parts: [sphere(ball_outer,50), sphere(ball_cavity,30),
                      subtract(ball_outer ∖ [ball_cavity])]   ← 布尔演算
③ 关系方程:  rests_on_centered → z球心 = z板顶 + 50 = 20 + 50 = 70
            xy球心 = xy板中心 = (0,0)                  ← 方程解出来的
④ 约束判定:  t(20) < r(50) → PASS;  球底(20)=板顶(20) 贴合无干涉 → PASS
⑤ 执行:      compose → CADService → STEP/STL
```

**验收数值**：V球壳 = 4/3π(50³−30³) ≈ 410,501 mm³；V板 = 200,000 mm³；
合计 ≈ **610,501 mm³**，2 连通体。STL 实测体积与理论偏差 < 1% 为 PASS。

## 六、演进规则（对齐上位文档四阶段）

| 阶段 | 内容 | 铁律 |
|---|---|---|
| V0（本版） | 3 体元 + 1 算子 + 1 关系 + 判定，空心球用例闭环 | 演算层零 LLM 调用 |
| V0.x | 算子: linear_pattern/mirror/fillet；关系: coaxial/gap/side_by_side | 每个词条=grammar.py 一行 + resolver 一段纯函数 |
| V1 | 语义回显确认流（歧义交还用户）；Anvil 旧 model_add_part 路径降级为兼容模式 | 新概念只进文法表，永不进 prompt 手写清单 |
| V2 | 自进化: resolver 无解 → 报能力缺口（Primordium EVOLUTION 流程），缺口以新词条形式合入 | LLM 永远不许"换个原语试试" |
